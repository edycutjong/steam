# How Kiro built this

**304 commits** in this repository are labelled `[kiro]` (`git log --format=%s | grep -c "^\[kiro\]"`): changes made in a Kiro session working through a spec's `tasks.md`, a bugfix spec or an agent workflow. The rest are labelled `[claude-direct]` (scaffold, measurement scripts, bench and provenance runs, interaction-QA CSS, evidence write-ups, CI/CD and the README); by lines changed they are about a third of the work (`git log --shortstat`, insertions plus deletions summed per label, 2026-11-27: roughly 64k lines in `[kiro]` commits and 35k in `[claude-direct]`). **Who wrote what:** the builder (a Claude agent) wrote every prompt Kiro received, often with the defect and the expected behaviour spelled out; Kiro wrote the specs, the code, the tests and the fixes under them. The sessions ran in Kiro's default (vibe) agent mode, executing `tasks.md` because the prompt said to; Kiro's task-execution UI was not used. The label is ours, so it is cross-checked against Kiro's own session store: **301 of the 304 `[kiro]` commits fall inside the time window of a recorded Kiro session** (`docs/kiro-evidence/sessions/ledger.json`), and every one of those 39 sessions has a condensed transcript in `docs/kiro-evidence/sessions/transcripts/`. Kiro was driven headless with `kiro-cli chat --v3 --no-interactive --trust-all-tools` from this folder; the flags are visible in `docs/kiro-evidence/probe-3.5.0.md` and in the sub-sessions Kiro launched itself (transcripts), while the launch line of each build session is not recorded in this repository.

This page is the causal chain: for each Kiro feature, the files that drove the work, what they changed, and where to check it. Then the gap we found in our own hook evidence, and what was planned and **not** built.

## 2. What the hooks saw, and what they did not

The hooks were tested on 2026-11-24 (kiro-cli 3.6.0): a live session tried four writes and two were refused (`src/steam/zz-hook-probe-voice.ts`, which called `speechSynthesis`, and `content/catalog.json`); both blocks are in `hooks.log`. Those hooks match Kiro's write tools (`fs_write`, `str_replace`).

**Then we measured what they could match: about 5% of the counted writes under `src/`** (the write-tool calls; calls, not lines). At 2026-11-25T20:43Z, `tools/evidence/session-ledger.ts` read Kiro's own session store for this workspace and counted, per tool call, what was written and whether a hook ran. Kiro wrote code mostly through its shell tool, not its write tools: **the ledger's write rule flags 543 shell commands as writing under `src/` (368 of them to non-test files) against 30 write-tool calls, and none of the 543 had a hook event** (172 of the 543 came in sessions before the hooks existed; the other 371 in the session that installed them, opened 2026-11-24 19:51Z, and the sessions after) (a heuristic count of commands, not a filesystem audit: it includes at least one false positive and misses some writers, see Limits below) (`docs/kiro-evidence/sessions/before/ledger.md`, the snapshot taken before the fix). `no-imitation` had written its last line at 2026-11-25T01:45Z although sessions after that wrote under `src/` by shell. The rule "speech or fake handwriting cannot enter `src/`" had been enforced by a gate that most writes walked around.

That became the bugfix spec `.kiro/specs/hook-coverage/bugfix.md` (12 `[kiro]` commits, red tests first):
- **`shell-gate`** (`.kiro/hooks/shell-gate.json`, PreToolUse, matcher `shell`): judges the text a shell command writes under `src/` with the same rules as `no-imitation`, and refuses a shell write of `content/catalog.json` whenever the command text shows it (a redirect, `tee`, `sed -i`, `cp`/`mv`, a literal path in an inline script, an `eval` or `bash -c` body); a path built from parts or a script run by name is not seen before it runs, and `src-scan` then checks the catalog's content. 0.06 s per call.
- **`src-scan-after-shell`** (`.kiro/hooks/src-scan-after-shell.json`, PostToolUse, matcher `shell`): after every shell command, judges the added lines under `src/` in the working tree, so a script that builds a path from parts is still seen, and (since a2a round 07) the lines any commit added since its previous run, so a command that writes and commits in one go is seen too. 0.11 s per call; it writes a line only when its verdict changes.
- **Steering** (`.kiro/steering/structure.md`, "Editing files"): edit files with the write tools.

Live probes in the same session, each line in `docs/kiro-evidence/hooks.log`:

| Probe | Line |
|---|---|
| heredoc writing `speechSynthesis` into `src/steam/zz-shell-probe.ts` (refused: the file was never created) | `shell-gate · src/steam/zz-shell-probe.ts · blocked: speechSynthesis (line 1), SpeechSynthesisUtterance (line 1)` |
| `echo '{}' > content/catalog.json` (refused; the catalog stayed byte-identical) | `shell-gate · content/catalog.json · blocked: a shell command writes the catalog; only npm run catalog writes it` |
| `python3 -c` building the path and the word from parts (the file was written, then deleted) | not seen by `shell-gate`; `src-scan · src/steam/zz-shell-probe2.ts · fail speechSynthesis (src/steam/zz-shell-probe2.ts:1)` |

After the fix, the same ledger (`docs/kiro-evidence/sessions/ledger.md`, re-run at the end of that session) reads 545 shell writes under `src/` (370 non-test), 36 write-tool calls, and 2 shell writes with a hook event: the new hooks' first session.

**What the unguarded writes wrote, checked afterwards** (asked by an outside judge-lens review, a2a round 09): `tools/evidence/rule-scan.ts` runs `no-imitation`'s own rules over what is already in the repository: every non-test file under `src/` at HEAD (106 files: 0 findings) and every line ever added under `src/` in history, each judged in its file at that commit (223 commits, 16,967 added lines: 0 findings). Positive control: the same rules over the 149 test files under `src/` and `tools/hooks/` (the scan skips the 142 under `src/`), which quote the forbidden words on purpose, fire 116 times. So the 368 shell writes to non-test files that no hook saw left no match for `no-imitation`'s patterns (`speechSynthesis`, `SpeechSynthesisUtterance`, a listed handwriting font or `cursive` on a font line, a handwriting-named import) in any committed non-test file under `src/`. Output: `docs/kiro-evidence/hook-coverage/retro-scan.txt`.

Limits, as measured: in headless `kiro-cli` a PostToolUse exit 2 only logs; it is not shown to the agent and does not stop it, so `src-scan` reports a script-written violation but cannot refuse it. A script run by name, `find -exec`, `xargs` and a diff applied from a file are not seen before they run; `shell-gate` logs the last one, and a write to a `$VAR` it cannot expand in a command that names `src/`, as `unresolved` instead of allowing it silently. The ledger's write rule is a heuristic with known false positives (one documented) and misses, stated at the top of `ledger.md`; treat its counts as approximate. Full write-up: `docs/kiro-evidence/hook-coverage/NOTES.md`.

**Changed after the spec, `[claude-direct]`** (an outside architecture review, a2a round 07; this build's Kiro credit allocation was spent): `shell-gate` now reads through `npx`/`bunx` and `eval`, keeps a `cd` inside `( … )` or `bash -c` from leaking out, expands a variable set earlier in the same command, and names the text it judged when a command writes two files; `src-scan` judges what a commit added since its previous run, and checks a changed catalog with `catalog-gate`'s own content check (gate pass, hashes, `review.json`) instead of trusting the words `npm run catalog` in the command, which `npm run catalog && node x.js` could spoof. Replayed over the 1,826 shell calls in the session store, none of these changes moves a call in or out of the ledger's count except variable expansion, so the ledger does not use it: with it, one more historical call (a write to `src/steam/derive.ts` through `$f`) would count, which would make 544 / 546 of the published 543 / 545. The published counts, and the video, use the rule as it stood when they were taken.

## 3. What the agents read, and who checked them
- The two readers' disagreements are not resolved by a model: `merged.json` keeps both readings, and the edition view shows each as `†[a | b]`.
- The eyes-only reading in `fixtures/gold-readings.json` was written **by the builder's agent (Opus 5.5, the same model family as the scribe), by eye, before any Kiro reader ran** — a separate check, not a human one. Scored against it, the scribe differs on 2 words and the second reader on 3; both scribe differences were flagged (`docs/EXPERIMENTS.md`, row 1).
- `content/recipes/quinces-marmalade/review.json` is signed by the builder's agent and says so ("not a human"); the edition view prints that line. A human sign-off is still owed. The catalog gate checks that review.json is well-formed, names a non-empty signer and was written against this gate.json's hash; it has never checked who the signer is (`tools/hooks/catalog-gate.ts`, `tools/steam-ingest/catalog.ts`). Its refusal text used to say "a person reviews a recipe", which promised more than the code checked, and was corrected in bd9062e.

## 4. Planned, not built
Stated so nobody has to infer it from silence:
- **No MCP server** (an IIIF server was planned; licences are resolved by code in `steam-ingest fetch`, eval E5) and **no rights-firewall hook**.
- **No Power**, and no `steam-ingest add --transcribe kiro` command for new pages.
- **No archivist agent.** Only the two readers.
- **No fog-model A/B** and **no spec-vs-vibe comparison** (`docs/EXPERIMENTS.md`).
- **No `tests-after-task` line**: PostTaskExec does not fire headless (`docs/kiro-evidence/probe-3.5.0.md`, result 9), and no IDE spec run was made.
- **Credits were not measured for the build.** A headless `/usage` is answered by the model instead of run (`docs/DX-REPORT.md`, 2026-11-24). Workflow runs do report per-step credit use in their `run_complete` event: run 3's two readers used 3.26 + 1.88 (unrounded 3.264 + 1.881) = 5.15 credits (`docs/kiro-evidence/sessions/transcripts/20261124T2053-76aa2bae.md`). No build total was kept. Session count: 26 build sessions + 13 spawned inside them (6 workflow readers, 6 hook and permission self-tests, 1 aborted) = 39; the 8 headless probe runs are separate (`docs/kiro-evidence/probe-3.5.0/`).

## 5. IDE vs CLI
Everything here ran through `kiro-cli` headless (3.5.0 for the probe, 3.6.0 for the hook self-test; the version of the other sessions is not recorded). Features that need the IDE (Markdown Review, the Spec Correctness panel, checkpoints, PreTaskExec / PostTaskExec hooks) are not used, and nothing on this page claims them. Friction we hit, dated: `docs/DX-REPORT.md`.
