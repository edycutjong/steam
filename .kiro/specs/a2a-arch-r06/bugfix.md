# Bugfix: a2a-arch-r06

A second review round of the a2a-arch-r05 fixes, at HEAD 7165162, found seven gaps (C1 to C7): the shelf retry that no screen can use, requests that never time out, a fallback that cannot go back to live, a wake lock that stops asking, a renderer clock that depends on one event, a hand-over timer that ignores a hidden tab, and a held reading that is still hidden from assistive tech on the spike page. Each is fixed with a test written first and committed red (`[kiro] a2a-arch-r06: red …`), then the fix (`[kiro] a2a-arch-r06: fix …`), then a preservation check. Every `a2a-arch-r05` test stays green. Nothing is pushed by this spec.

Terms. "Transport failure": a fetch rejection, a body that did not arrive, HTTP 408, 429 or 5xx (as in r05 B5). "Transient rejection": a `Rejection` whose load ended on a transport failure after the retries. "Deadline": the time after which a request is aborted by the app. "Static pane": `StaticPane`, the pre-rendered fog and note images that replace the live canvas. "Hand-over": the move from Cook Mode to "The hand, quoted" after the last wipe.

## Current Behavior

1. **C1.** `App` loads the shelf once (`useEffect(…, [loader, announce])`). A rejection that ended on transport (r05 B5 does not cache it) is a `Rejection` like any other, so a catalog id whose load failed renders the plain `NotFound` until the page is reloaded, even when the network is back. The B5 cache eviction is never used by a screen.
2. **C2.** Nothing aborts a request that hangs. `createShelfLoader` awaits `fetchFn('/recipes/<id>/recipe.json')` with no deadline, `fetchOk` in `src/steam/assets.ts` calls `fetch(url, { signal })` with only the caller's signal, and `SteamPane` calls `fetch('<stem>.json')` with none. A hung request never settles, so the B5 retry and the note-failure path (R15.12) never start, and the shelf, the pane or the glass waits for ever.
3. **C3.** `SteamGlass` computes `useStatic = reducedMotion || noWebGl || contextLost` on every render. `reducedMotion` is reversible by the media query. When it goes false during a hold, the effect keyed on `[loaded, status]` builds a new renderer with `lead: Infinity`: the pane is fogged, the reveal effect has already been consumed by the reveal gate, and Cook Mode computes `writing` (`ns === 'revealed' && noteAttr !== 'held'`), so the wipe control does nothing until the screen is remounted.
4. **C4.** `createWakeLock`'s `onGesture()` returns unless the status is `refused`. After a browser release has been answered once (`answered === true`), a second browser release leaves the status `idle` and nothing is pending. No gesture asks again, though the page is visible and the user is tapping the screen.
5. **C5.** The renderer's reveal clock stops on a `visibilitychange` to hidden and restarts only on the `visibilitychange` to visible (`handleVisibility`). r05 B8 records that a restored page can come back visible without that event. Then `frame()` returns early for ever (`hiddenAt !== null`), `clockNow()` stays on the hidden instant, the glass never advances and the wipe control stays blocked.
6. **C6.** `Cook` hands over to "The hand, quoted" with `setTimeout(…, WIPE_MS)` on the wall clock. Since r05 B1 the final sweep stands still while the tab is hidden, but this timer does not: hiding the phone within 1.4 s of the last wipe sends the cook to the next screen without the sweep they made.
7. **C7.** `SteamPane` marks the held reading `aria-hidden="true"` (`p.note-reading[data-note-reading]`), the defect r05 B9 fixed in Cook Mode. The words are in the polite live region once, and the next message replaces them there.

## Expected Behavior

1. **C1.** A `Rejection` that ended on transport carries `transient: true` (a rejection from a 404 or a content failure does not). While the shelf result holds one, `App` runs `loader()` again on the window `online` event. The not-found screen shown for a catalog id whose load failed on transport says so in one short line and has a "Try again" button that runs the load again (copy in `src/copy/strings.ts`, at least 44 px high, keyboard operable, and the same route). A recipe that then loads replaces the not-found screen on the same route. A 404 or a content failure keeps today's plain `NotFound`: no line, no button. An id the catalog does not list is also plain `NotFound`.
2. **C2.** One small helper aborts a fetch after a deadline, with an injectable clock (timer functions) for tests. The recipe fetch (request and body) has a 10 s deadline and ends as a transport failure, so B5 retries it. A note-asset fetch has a 15 s deadline and ends as an `AssetError` for that field, so the existing failed-pane path runs (`PaneStage` drops the reveal, Cook Mode shows the typed transcription, R15.12). `SteamPane`'s `<stem>.json` fetch has a 10 s deadline and ends in its existing `.catch`, which leaves its text state empty (it has no error state of its own; the glass keeps its own `error` status for the assets). An abort the caller asked for (its `signal`) is still re-thrown as an abort and is never turned into an `AssetError`. The timer is cleared as soon as the request settles.
3. **C3.** Once the static pane has replaced the live one for a mounted note, whatever the reason, it stays static for that note. The next note's pane (a new mount) may be live again. Switching reduced motion off never produces a fogged pane for a revealed note.
4. **C4.** `onGesture()` also asks again when the status is `idle`, nothing is pending and the lock has not been released by us. It does nothing when the status is `held`. The automatic re-acquire after a browser release stays at most once per hide/show or gesture, so there is no loop.
5. **C5.** When a frame arrives, or `startReveal()` or `wipe()` is called, while `hiddenAt` is set and the visibility source says the page is not hidden, the renderer applies the shift `handleVisibility` applies on show (`revealStart`, `t0`, `lastNotify`, `lastStats` by the gap, `lastFrame` NaN) and carries on. The listener path is unchanged.
6. **C6.** The hand-over waits for `WIPE_MS` of visible time. The countdown pauses while `document.visibilityState === 'hidden'`, resumes on `visibilitychange` to visible, and on `pageshow` and `focus` when the page is visible (as r05 B8). It is cancelled when Cook Mode closes. Visible behaviour is unchanged: 1400 ms.
7. **C7.** The held reading in `SteamPane` is in the accessibility tree: no `aria-hidden` on it or on an ancestor. The canvas stays `aria-hidden`. No second live announcement is added.

## Unchanged Behavior

1. A 404, an invalid body, a schema failure, `checkCookable` and provenance withholding stay terminal, cached and never retried; they show the plain `NotFound`. The B5 retry delays, the cache eviction of a transient result and the shared in-flight load. (C1, C2)
2. The hash route, the `NotFound` heading, back link and focus handling. The shelf and edition screens, which never show a rejection. (C1)
3. A fetch that settles before its deadline behaves as before, headers and body. A caller's abort stays an abort. The `AssetError` fields and messages of failures that are not timeouts. (C2)
4. r05 B4: a fallback chosen after a live state exists resumes from it. A reduced-motion page that never had a live state waits for `startReveal`. A context loss keeps its 2 s restore window. (C3)
5. A granted lock still gives `data-wake="held"`, a refusal shows no text, no API gives `unsupported`; r05 B7 (a) late sentinel released, (b) one re-acquire after a browser release and no loop, (c) a refusal retried by a gesture. A gesture after Cook Mode closed asks for nothing. (C4)
6. r05 B1: the clock stands still while hidden, the gap reaches neither the reveal nor `stats` nor the governor. A `fogged` pane with `lead: Infinity` stays fogged until `startReveal`. A hidden page that never became visible stays frozen. (C5)
7. The hand-over still happens once, after the last wipe, and only when Cook Mode is still open. The Cook wall clock and the scheduler keep running while a phone sleeps. (C6)
8. `SteamPane`'s live region, button, credit and `DisagreeDescription`; the e2e assertions on the spike page. Shaders, design tokens and pinned visual bounds are not touched. (C7)
9. The service worker lifecycle and the catalog gate claim (`tools/steam-ingest/catalog.ts`, CI `npm run props`) are out of scope and untouched.
