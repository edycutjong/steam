# Bugfix: hook-coverage

The three write gates of this repository (`no-imitation`, `catalog-gate`, and the `hooks.log` evidence they write) are PreToolUse hooks with matcher `write`. Kiro runs that matcher on `fs_write` and `str_replace` only. Measured from this workspace's own session store (`~/.kiro/sessions/5eb0616fc3b77bab/sess_*/messages.jsonl`, `payload.type == "tool_call"`), across the 38 sessions before this one: about 25 tool calls wrote under `src/` with a write tool, while about 700 `execute_bash` commands wrote under `src/` (redirects, heredocs, `sed -i`, interpreter scripts). In the last three sessions (cook-mode-qa-r1, a2a-arch-r05, a2a-arch-r06) there were 79, 118 and 72 `execute_bash` calls and 1, 2 and 2 `fs_write` calls, the `fs_write` calls only on `.kiro/specs/*/bugfix.md`. `ContextualHookInvoked` events appear only for `fs_write`. So `no-imitation` last wrote a line to `docs/kiro-evidence/hooks.log` at 2026-11-25T01:45Z although many `src/` files were created and changed after that, and `catalog-gate` cannot see a shell write of the public catalog (`docs/kiro-evidence/README.md` says so).

Each item below is fixed with a test written first and committed red (`[kiro] hook-coverage: red …`), then the fix (`[kiro] hook-coverage: fix …`), then a preservation check. Nothing is pushed or deployed by this spec. Every file of this spec is written with the write tools (`fs_write`, `str_replace`), because that is the defect.

Terms. "Shell write": a shell command (`execute_bash`, tag `shell`) that creates or changes a file, by redirect, heredoc, `tee`, `sed -i`, `cp`/`mv`/`install`, `patch`/`git apply`, or an interpreter script (`python3`, `node`, `perl`, `ruby`) that calls a file-writing API. "Introduced text": the text a command puts into the file, as far as the command text shows it (heredoc bodies, `echo`/`printf` payloads, the inline script). "The catalog": the public recipe list, spelled in code as `'catalog' + '.json'` (R35.5). "The ledger": `docs/kiro-evidence/sessions/ledger.json` and `ledger.md`.

## Current Behavior

1. **H1.** Nothing in the repository measures which tool wrote what. The claim "the hooks do not see shell writes" is prose in one README sentence and in this spec's header, not a number a reader can reproduce.
2. **H2.** No hook runs on a shell command. `src/steam/zz-shell-probe.ts` written by `cat > … <<'E'` with a call to the speech API passes through unchecked, and so does `echo '[]' > content/<the catalog>`. The only barrier to the second is that agents are told to use `npm run catalog`.
3. **H3.** A script can write a file the command text never names (`node scripts/x.ts` that writes into `src/`, a path built from parts). No hook looks at the working tree after a shell command, so such a write is never judged by `findViolations`, and the catalog can change without `catalog-gate`.
4. **H4.** The steering files say what the hooks are, not that file edits belong to the write tools. `docs/kiro-evidence/README.md` has no `<who>` row for a shell gate, and states "A `catalog-gate` block covers write tools only" as a standing limit.
5. **H5.** No evidence shows a shell hook firing in a Kiro session of this repository. Only `fs_write` hook events exist in the session store.
6. **H6.** After a fix there is no before/after count to compare with.

## Expected Behavior

1. **H1.** `tools/evidence/session-ledger.ts` has a pure function `buildLedger(sessions, commits)` and a thin CLI. Given a sessions folder (positional argument, or `--workspace <path>` resolving `~/.kiro/sessions/<hash>`), it reads every `sess_*/session.json` and `messages.jsonl` and writes `docs/kiro-evidence/sessions/ledger.json` and `ledger.md`. Per session: id, title, createdAt, lastModifiedAt, modelId, agentMode, counts of tool calls by tool name, the number of `execute_bash` commands that write under `src/` (rule below; total and non-test), the `fs_write`/`str_replace` paths under `src/`, the number of `ContextualHookInvoked` events by hook name, how many of the shell writes under `src/` had a hook event during the call, and the `[kiro]` commits (hash, subject, author time) whose author time falls inside the session window. It copies no prompt text, assistant text, tool output or command text: titles, counts, paths and commit hashes only. The detection rule is `analyzeShell` in `tools/hooks/shell-writes.ts` (one rule, used by the ledger and by the gate), stated in the ledger files and tested. The ledger of this repository, run before any hook exists, is committed as the "before" evidence. Red test: a fixture session whose shell call is a heredoc write to `src/x.ts` is counted as one shell write under `src/` that no hook saw.
2. **H2.** `.kiro/hooks/shell-gate.json` (PreToolUse, matcher `shell`) runs `tools/hooks/shell-gate.ts`. Its tests use `docs/kiro-evidence/hook-coverage/shell-event.json`, the shell hook stdin recorded in the session that wrote this spec (tool name `execute_bash`, `tool_input.command`). When the command writes under `src/` (non-test file), it runs `no-imitation`'s `findViolations` on the introduced text and refuses with exit 2 and the rule text on a violation. When the command writes the catalog by any means, it refuses with the reason `catalog-gate` gives (`npm run catalog` is the only writer). It appends one `hooks.log` line per command that targets `src/` (non-test) or the catalog: `shell-gate · <target> · blocked: … | pass (…)`. A command that writes neither appends nothing. A command it cannot parse is allowed and logged as `unparsed` when it names `src/` or the catalog; it is never allowed silently.
3. **H3.** `.kiro/hooks/src-scan-after-shell.json` (PostToolUse, matcher `shell`) runs `tools/hooks/src-scan.ts`: `findViolations` over the added lines of non-test files under `src/` (`git diff -U0` plus untracked files) and a check of the catalog against HEAD and against the rule "only `npm run catalog` writes it". It appends one `hooks.log` line (`src-scan · <target> · fail <what> (<file>:<line>) | pass (<n> files)`) only when the judged state changed since its last line (a content hash kept under `node_modules/.cache/steam-hooks/`), and exits 2 with the finding on a fail. Both hooks start with `node`, and the per-call time is measured and written down.
4. **H4.** One short steering rule says: write and edit files with the write tools; shell writes under `src/` and to the catalog are gated by `shell-gate` and `src-scan` and logged. The `hooks.log` table in `docs/kiro-evidence/README.md` has the two new `<who>` values, and the sentence "covers write tools only" is replaced by what was measured after the fix.
5. **H5.** After H2 to H4 are committed, three probes run in the session (the hooks hot-load; this was observed when recording the shell event): a heredoc write of `speechSynthesis` to `src/steam/zz-shell-probe.ts`; `echo '{}' > content/<the catalog>`; an interpreter one-liner that builds the path from parts and writes `speechSynthesis` to `src/steam/zz-shell-probe2.ts`. Each is recorded in `docs/kiro-evidence/hook-coverage/NOTES.md` with the `hooks.log` line it produced, or "no line" and why. A probe that does not behave as expected is the result: it is written down and its file is never staged. Every probe file is deleted afterwards and the catalog is byte-identical to HEAD.
6. **H6.** The ledger is run again at the end. `NOTES.md` has before/after figures for this session: write-tool calls against shell writes under `src/`, and hook invocations.

## Unchanged Behavior

1. `no-imitation` and `catalog-gate` on `fs_write` and `str_replace`: their hook files, matchers, rules, log lines and tests. (H2, H3)
2. A shell command that writes neither `src/` nor the catalog: no `hooks.log` line, exit 0, no output. Reads, test runs, `git` commands, writes to `docs/`, `tools/`, `e2e/`, `scripts/`, `content/recipes/`, `/tmp`. (H2)
3. Test files under `src/` (`*.test.ts`, `*.test.tsx`, `src/__tests__/`) are not judged, as in `no-imitation`. (H2, H3)
4. `npm run catalog` and `steam-ingest catalog` remain the only writers of the catalog and are never blocked. The R35.5 test (no other non-test source file names the catalog file as a literal) stays green. (H2, H3)
5. A hook's own bug or an unexpected exception warns and allows (exit 1), never blocks. A log write failure never changes the verdict. (H2, H3)
6. The ledger never contains prompt text, assistant text, tool output or command text. (H1)
7. `docs/KIRO.md`, `docs/EXPERIMENTS.md` and `README.md` are not edited. Shaders, tokens, copy strings and pinned visual bounds are not touched. (all)
